Verdict

The short of it

What the numbers support, and how far.

Hermes Agent solved more tasks than OpenBot in both tracks: {{fh_n}} to {{fo_n}} from a clean start, and {{lh_n}} to {{lo_n}} with a lived-in profile. From a clean start, the lead comes from systems and security tasks and from science and math. With a lived-in profile it spreads across more families.

OpenBot was cheaper. From a clean start it spent {{fo_cps}} per solved task against Hermes's {{fh_cps}}. With learning included, the gap widens to {{lo_cps_l}} against {{lh_cps_l}}, because Hermes's learning step costs far more than OpenBot's.

The lead is real in this run but small. On the same {{n_tasks}} tasks, Hermes solved {{f_only_h}} that OpenBot missed, and OpenBot solved {{f_only_o}} that Hermes missed. A split that uneven would turn up by chance about one time in {{f_chance}}, so a second run could narrow it.

Method

How it was run

The code, data and full incident log are on GitHub.

The tasks

All {{n_tasks}} tasks of Terminal-Bench 2.0: building software, fixing code, configuring servers, cracking puzzles, training small models. Each runs in its own container and is graded by its own tests.

One attempt per task, with the benchmark's standard time limits.

Matched settings

Both harnesses used DeepSeek V4.1 Flash through OpenRouter at reasoning effort high. Each harness's own records confirm the model and effort on every trial.

Same machine, same prompt, default skills and settings. Hermes Agent v0.23.1 ran as its command-line tool. OpenBot 0.65.0 ran as its desktop app, driven through its own window.

Two tracks

Clean start: a fresh profile for every task.

Lived-in: one profile per harness, carried through all {{n_tasks}} tasks in a fixed order. After each task the harness ran its own learning step. Hermes reviews the session and writes skills and memories. OpenBot reviews the thread and writes memories.

Scoring and cost

A task counts as solved only when its tests pass. A task whose grading ran out of time counts as a failure.

Cost uses each harness's own token counts at one flat rate: ${{p_in}} per million input tokens, ${{p_cached}} cached and ${{p_out}} output. Time is the harness's own working time, without startup.

Failures

Notable failures

Quoted word for word from the run logs.

OpenBot · cancel-async-tasks · clean start
“Checked by running: peak concurrency was exactly 3 for 10 jobs at limit 3, all jobs completed, error path and cleanup verified […] Sending SIGINT mid-run printed cleanup for both running jobs before KeyboardInterrupt propagated, and unstarted jobs never began.”

The tests found: with more tasks than open slots, the cleanup message printed 0 of the 2 times required. Hermes Agent passed this task in {{q_cancel_h_min}} minutes.

Hermes Agent · polyglot-c-py · clean start
“Verified (all with real runs): gcc /app/polyglot/main.py.c -o /app/polyglot/cmain — exit 0, empty stderr.”

The tests found: the task wanted main.py.c alone in that folder. Hermes left its compiled test program, cmain, beside it. OpenBot passed.

OpenBot · compile-compcert · clean start
“Target crashed”

The agent's build of the CompCert compiler filled the task's {{q_cc_limit}} memory limit, with compiler processes holding {{q_cc_task}}. The kernel stopped OpenBot's own window process first, a {{q_cc_victim}} process. Chromium-based apps mark that process as the first to go, so the session ended with the work unfinished.

Hermes Agent · caffe-cifar-10 · lived-in
“Error: Gateway disconnected; turn outcome is unknown.”

The same kind of failure with a different victim. During a 12-process C++ build in a {{q_caffe_limit}} container, the kernel stopped the largest single process, which was Hermes's own gateway at {{q_caffe_victim}}. Across all kept trials, OpenBot's own processes were stopped this way in {{oom_o}} and Hermes's in {{oom_h}}.

Caveats

Read before quoting

Limits of a single run on one model.

A small sample

{{n_tasks}} tasks is a small sample. The 95% intervals for the two harnesses overlap in both tracks, and the head-to-head split ({{f_only_h}} to {{f_only_o}}) would turn up by chance about one time in {{f_chance}}.

One model, one setting, one attempt

These results hold for DeepSeek V4.1 Flash at high effort, with one attempt per task. A stronger model, another effort level or repeated attempts could change the order.

How OpenBot was run

OpenBot is a desktop app. It ran inside each task's container, and a script typed the task into its window and waited for it to finish, the way a person would. Hermes ran as its command-line tool. When our script failed, the attempt was thrown out and rerun.

Reruns

{{disc_n}} attempts were thrown out because our setup or automation broke them, or because a rollback undid them. Their {{disc_cost}} of model use is not counted anywhere. The same rule applied to both harnesses.
